## Doc Structure

```
docs/
├── SKILL.md              # Quick-reference for models using the framework
├── MODEL_NOTES.md        # This file
├── guide/                 # Hand-authored narrative guides (20 files)
│   ├── index.md          # Landing page with module table and conventions
│   ├── recipes.md        # Cross-module patterns (download+verify, locking, etc.)
│   └── {module}.md       # Per-module guides (18 files) — patterns, gotchas, examples
└── api/                  # Generated API reference
    ├── index.md          # Function dictionary (alphabetical, 1117 entries)
    ├── {module}.md       # Per-module function listings (generated)
    └── {module}/{fn}.md  # Per-function pages (signature, params, source)
```

- **guide/** — hand-authored narrative. Per-module pages cover what the module does, key function categories with examples, common patterns, and gotchas. Edit directly.
- **api/** — generated by `tools/api-gen.sh`. Do not hand-edit; regenerate.
- **api/index.md** — generated by `/tmp/build-dict.sh` (post-processing after api-gen). Regenerate after api-gen runs.


## Things to Be Aware Of

- **Minifier can hang** — `MINIFY=1` builds are slow/unreliable; use `MINIFY=0`
- **AGENTS.md** at repo root has build commands and conventions
- **`tools/wiki-gen.sh`** is the old generator — superseded by `tools/api-gen.sh`
- **API pages track source comments** — thin comments → thin API docs. The guide pages are where rich descriptions live
- **`docs/api_bak/`** may exist as reference from the old generator; safe to delete
